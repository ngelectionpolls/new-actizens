### Task 2: Motion system — orchestrated hero entrance, calmer scroll reveals, page crossfade

Design intent: ASIF documents evidence and mobilises citizens; motion should feel **deliberate, precise and calm** (no bounce, no flourish). Spend boldness in ONE place per page: the hero entrance. Everything else gets quieter than today.

Create `public/motion.js` (ES module, no dependencies) exporting:
- `reduceMotion` — the `matchMedia('(prefers-reduced-motion: reduce)')` MediaQueryList.
- `heroSequence({lines=[], supporting=[], media=[], accent=[]})` — plays the page-load entrance once:
  - `lines` (headline line elements): each animates `{opacity:0, transform:'translateY(18px)'}` → `{opacity:1, transform:'none'}`, duration `720ms` (`--duration-hero`), easing `cubic-bezier(.23,1,.32,1)`, stagger 70ms per line, `fill:'backwards'`.
  - `supporting` (eyebrow, intro paragraph, CTA row, badges): same keyframes with 10px travel, 520ms, starting 180ms after the last line's start, stagger 60ms.
  - `media` (hero image(s)): `clip-path: inset(0 0 0 100%)` → `inset(0 0 0 0)` combined with `transform: scale(1.06)` → `scale(1)`, 900ms, easing `cubic-bezier(.32,.72,0,1)` (`--ease-drawer`), starting at 80ms. The wipe runs from right to left so the image is "laid down" toward the headline. Images inside a container with `overflow` visible must not visibly spill: apply clip-path to the image element itself.
  - `accent` (small decorative rules, e.g. the gold underline in the desktop quote panel, if identifiable): `transform: scaleX(0)` → `scaleX(1)`, `transform-origin:left`, 480ms, after the media finishes 60%.
  - Must be a no-op when `reduceMotion.matches` or when `Element.prototype.animate` is missing. Must preserve each element's existing computed transform (read `getComputedStyle(el).transform`; compose the start transform as `base + ' ' + delta` and end with `base`), as the current `enter()` in experience.js does — Figma nodes carry rotation/flip transforms.
  - Return the array of Animation objects.
- `revealOnScroll(elements, {stagger=60, maxStagger=240})` — replaces the current per-page "entrance language". One consistent reveal: `{opacity:0, transform:'translateY(12px)'}` → `{opacity:1, transform: base}`, duration 420ms (`--duration-reveal`), easing `--ease-out` value, `fill:'backwards'`. Stagger is computed per parent container (index among the observed siblings that share the same `parentElement`), `min(index*stagger, maxStagger)` — not by global index. Use one IntersectionObserver with `threshold:.12, rootMargin:'0px 0px -40px 0px'`, call `observer.unobserve(el)` when triggered. Elements already in the viewport at call time (i.e. part of the first screen) must NOT be hidden-then-revealed; skip them (they are covered by the hero sequence or simply shown). Skip when the user is navigating by keyboard (keep the existing `keyboard` flag behaviour in experience.js: pass a predicate or keep the check in the caller) and when reduced motion is on. If reduced motion turns on mid-session, disconnect and finish running animations (existing behaviour in experience.js line ~37 — keep it working).

Wire it up:
- `public/experience.js`: import from `/motion.js`. Replace the existing `enter(heading, language[page])` hero call and the `language` map with `heroSequence(...)`:
  - Desktop (viewport > 1024px): the hero is the first visual block of `.design-canvas`. Lines = the `<p>` children of the element with `[aria-level="1"]` inside `.design-canvas` (the h1 is split into one `<p>` per line; if it has no `<p>` children, use the element itself). Supporting = other leaf text/button blocks whose top is within the hero region (top < canvas top + 640px × the canvas scale, and left < 50% of the canvas width), excluding the header, the h1 and anything inside `.site-header`; cap at 8 elements. Media = `img` elements in that region wider than 300px rendered size. Verify per page visually (home, about, programs, events, gallery, contact, donate, resources) that the sequence picks sensible elements; adjust the heuristic, not per-page hacks, unless one page truly needs it.
  - Mobile (≤1024px): lines = `.mobile-hero h1`, supporting = `.mobile-hero .eyebrow`, `.mobile-hero .hero-copy > p`, the first `.mobile-section .dialog-actions` directly after the hero if present; media = `.mobile-hero .hero-image`.
  - Scroll reveals: call `revealOnScroll` on card collections only: `.experience-card`, `.experience-steps li`, `.mobile-card`, `.vision-card`, and the desktop Figma image cards already selected by the existing `[class*="shadow-"]` filter. **Stop** revealing `.experience-intro`, `.faq-item` and `.mobile-banner` (section headings, FAQ rows and banners simply appear — this removes the generic "everything fades up" feel).
